# Tutorial 2 — Supabase: PostgreSQL, RLS e Realtime

## 1. O que é o Supabase?

O Supabase oferece banco PostgreSQL na nuvem, controle de acesso e eventos em tempo real. Neste projeto ele recebe os avisos e informa os aplicativos conectados quando surge um novo registro.

Painel: https://supabase.com/dashboard

## 3. Criar a tabela pelo SQL Editor

1. No menu, abra **SQL Editor**.
2. Clique em **New query**.
3. No GitHub, abra `supabase/setup.sql`.
4. Copie o conteúdo inteiro e cole no editor.
5. Clique em **Run**.

Arquivo usado:
https://github.com/gilbertocorrea-cmd/engcomp-alert/blob/main/supabase/setup.sql

O script cria a tabela `public.notifications` com estas colunas:

| Coluna | Tipo | Finalidade |
| --- | --- | --- |
| `id` | `bigint` | Código único, gerado automaticamente |
| `title` | `text` | Título do aviso |
| `body` | `text` | Texto do aviso |
| `created_at` | `timestamptz` | Data e hora de criação |

As colunas `title` e `body` são obrigatórias. O script limita o título a 150 caracteres e a mensagem a 2.000.

## 4. Entender o SQL

```sql
create table if not exists public.notifications (
  id bigint generated by default as identity primary key,
  title text not null check (length(trim(title)) between 1 and 150),
  body text not null check (length(trim(body)) between 1 and 2000),
  created_at timestamptz not null default now()
);
```

- `create table`: cria uma tabela.
- `if not exists`: evita erro caso já exista.
- `identity`: gera IDs automaticamente.
- `primary key`: identifica cada linha.
- `not null`: impede valores ausentes.
- `check`: aplica regras de validação.
- `default now()`: preenche o horário automaticamente.

## 5. O que é RLS?

RLS significa *Row Level Security*, ou segurança por linha. Ele controla quais operações um cliente pode realizar.

O script habilita o RLS e cria duas políticas **para a demonstração acadêmica**:

- `engcomp_read_demo`: permite ao cliente anônimo executar `SELECT` (ler).
- `engcomp_insert_demo`: permite ao cliente anônimo executar `INSERT` (inserir).

Não existe política para editar ou excluir avisos no cliente anônimo.

**Importante:** essa configuração deixa avisos legíveis e inseríveis sem login. Não use para informações pessoais, dados sigilosos ou em produção. Num sistema real, configure autenticação e permissões por função.

## 6. Como funciona o Realtime?

O script inclui `public.notifications` na publicação `supabase_realtime`.

Isso permite que o aplicativo receba eventos `INSERT` quando alguém cria um aviso.

Para conferir no painel, procure **Database > Publications** e verifique se `notifications` está em `supabase_realtime`. Os nomes dos menus podem variar conforme a interface.

## 7. Onde pegar a URL e a chave

No projeto Supabase, abra **Project Settings** e procure **API** ou **API Keys**.

Você precisa de:
- URL do projeto.
- Chave **publishable** ou **anon** pública.

**Nunca** coloque a chave `service_role` ou uma chave secreta administrativa em React Native.

O arquivo `src/services/supabase.js` já contém a conexão pública padrão desta atividade.

## 8. Como conectar outro banco

Na pasta local do projeto:

```bash
cp .env.example .env
```

Abra `.env` no editor e configure:

```env
EXPO_PUBLIC_SUPABASE_URL=https://SEU_REF.supabase.co
EXPO_PUBLIC_SUPABASE_ANON_KEY=SUA_CHAVE_PUBLICA
```

O Expo usa essas variáveis no aplicativo. Não coloque dados secretos em variáveis `EXPO_PUBLIC_`, porque elas são incluídas no código distribuído.

Para recarregar após a mudança:

```bash
npx expo start --clear
```

## 9. Testar o banco

1. Vá a **Table Editor**.
2. Abra `public.notifications`.
3. Envie um aviso pelo celular.
4. Verifique se aparece uma nova linha com título, mensagem e horário.

Se o registro aparece, a gravação está funcionando. Para testar o Realtime, mantenha outro celular aberto no aplicativo e verifique se recebe o alerta.

## Resumo

PostgreSQL = salva os dados.
RLS = define quem pode ler e inserir.
Realtime = comunica novas inserções sem precisar atualizar a tela.
